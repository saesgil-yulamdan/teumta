# 혼잡도 판단 기준

## 데이터 구분

| 데이터 | 의미 | 캐시/저장 | 사용처 |
|---|---|---|---|
| SK Puzzle | 현재 장소 혼잡도 | 서버 메모리 5분, DB 미저장 | 당일 상태와 우회 강조 |
| KTO 집중률 | 향후 날짜별 집중률 | 지역 단위 서버 메모리 6시간, DB 미저장 | 덜 붐비는 날짜 참고 |

두 데이터는 단위와 산정 기준이 다르므로 서로 대체하거나 직접 비교하지 않습니다.

## 실시간 단계

SK 응답의 `type=1`만 실시간으로 사용합니다. `type=2`·`type=3`은 실시간 값의 대체재로 쓰지 않습니다.

| SK `congestionLevel` | 내부 단계 | 화면 의미 |
|---|---|---|
| 1 | `RELAXED` | 여유 |
| 2 | `NORMAL` | 보통 |
| 3 | `CROWDED` | 혼잡, 우회 코스 강조 |
| 4 | `VERY_CROWDED` | 매우 혼잡, 우회 코스 강조 |

공식 근거가 없는 공통 점수는 만들지 않습니다. KTO 집중률에도 임의 혼잡 등급을 붙이지 않고 오늘과 30일 중앙값의 상대 차이만 표시합니다.

## 실패 처리

- SK가 장소를 지원하지 않음: `404 CONGESTION_DATA_NOT_FOUND`, 화면은 “미제공”
- SK 장애/timeout: “확인 불가”, KTO 값으로 대체하지 않음
- KTO 데이터 없음: 날짜별 섹션만 숨김
- `CROWDED` 이상이라는 실시간 근거가 없으면 자동 우회 팝업을 띄우지 않음

## 코스와의 관계

실시간 혼잡도는 사용자가 우회 코스를 볼지 판단하는 근거입니다. 코스 후보 정렬에 각 정류지의 혼잡도를 넣지는 않습니다. 코스 포함 가능 여부는 제한시간, TMAP 보행 경로, 운영시간·휴무일 규칙으로 판단합니다.

복귀 예정 시각의 혼잡도를 예측하지 않습니다. KTO 값은 날짜 단위라 특정 미래 시각 판단에 사용할 수 없습니다.

## 보존 코드

DB 적재형 집중률 서비스와 스케줄러 소스는 과거 구현으로 남아 있지만 현재 서버 시작 과정과 공개 라우터에서 사용하지 않습니다.
