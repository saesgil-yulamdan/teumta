# 출시·배포 체크리스트

코드 기준일: 2026-09-14 KST. 스토어, 배포 서버, API 키와 외부 서비스 상태는 제출 직전에 다시 확인합니다.

## 코드에서 확인된 항목

- [x] 현재 모바일 공개 API는 DB 없이 구성됨
- [x] 서버 기동에서 Prisma 연결·migration·예측 적재 스케줄러 제거
- [x] `/health`가 DB를 조회하지 않음
- [x] 코스 생성 시 명확한 휴무·운영 종료·브레이크타임 후보 제외
- [x] 코스 요청 모바일 timeout 30초, 일반 요청 10초
- [x] 성공/오류 응답 envelope과 오류 코드 처리 통일
- [x] 주요 모바일 네트워크·알림·혼잡 polling 로직을 도메인 훅으로 분리
- [x] Redis는 현 단계에서 보류하고 서버 완성 코스 2분 캐시 적용
- [x] 서버·모바일 자동 검사 통과 여부는 각 변경 시 CI와 로컬에서 재확인

## 배포 전 필수

- [ ] 현재 revision을 서버에 배포하고 `/health` 응답에 DB 상태가 없는지 확인
- [ ] 외부 API 키 4종을 노출 없이 확인
- [ ] 대표 지역 검색 → 상세 → 30/60/90분 코스 → 진행 흐름 실기기 확인
- [ ] 명확한 오늘 휴무 장소가 코스에서 제외되는 사례 실데이터 확인
- [ ] 느린 코스가 10초를 넘더라도 30초 안에 성공하거나 timeout 안내가 나오는지 확인
- [ ] `429 PUBLIC_API_RATE_LIMITED`와 `Retry-After` 표시 확인
- [ ] App Store/TestFlight의 현재 버전·build number·승인 상태 재확인

## 기존 DB를 종료하려면

- [ ] DB 비의존 서버 revision 배포 완료
- [ ] 과거 Place/Route/Trip/집중률 데이터를 더 사용하지 않는다는 팀 결정
- [ ] 최신 백업 다운로드
- [ ] 임시 DB 복원 및 주요 테이블/행 수 검증
- [ ] DB backup workflow 중단 시점 결정

코드상 DB는 현재 서비스에 필요 없지만 운영 데이터 삭제는 복구 가능성을 검증한 후 별도로 수행합니다.

## 관측

관리자 analytics를 운영하지 않습니다. `public_api_usage` 로그와 외부 API 제공자 대시보드에서 엔드포인트별 상태·소요시간·쿼터를 봅니다. Redis 도입은 다중 인스턴스, 캐시 미스에 따른 쿼터 부족, 분산 rate limit 필요가 관측될 때 재검토합니다.
